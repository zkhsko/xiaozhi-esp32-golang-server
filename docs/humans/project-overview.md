## 项目目标

首期只为当前 `xiaozhi-esp32` 固件实现最小可用的 Go 语音服务端。固件源码和协议保持不变，部署时只需把设备 `ota_url` 指向本服务。

完整链路为：

```text
设备语音 -> 百炼 ASR -> qwen3.7-flash -> 百炼 TTS -> 设备播放
```

语音闭环优先于设备管理、数据持久化、部署包装和其他周边能力。

## 首期能力

- 最小配置发现接口，直接下发 WebSocket 地址、共享 Token 和协议版本 1。
- WebSocket v1 hello、文本消息和双向 Opus 音频。
- 固件默认的 `auto` 收音模式，以及 `manual` 模式兼容。
- 百炼服务端 VAD、流式识别、流式 LLM 和按句流式 TTS。
- 同一连接内有限多轮上下文、显式中断和断线重连。
- 可配置的并发保护上限、资源上限、超时和必要日志。

## AI 方案

| 能力 | 首期实现 |
| --- | --- |
| ASR | 百炼 `qwen-audio-3.0-asr-flash-streaming`，使用服务端 VAD |
| LLM | 百炼兼容接口，`qwen3.7-flash`，流式输出并关闭思考 |
| TTS | 百炼 `qwen-audio-3.0-tts-flash`，音色 `longanlingxi` |
| 音频输出 | 24 kHz 单声道 PCM，由服务端编码为 60 ms Opus 帧 |

ASR、LLM、TTS 使用三个独立能力边界，后续可以分别增加其他服务商适配器。首期每项只有百炼实现，不开发动态选择、自动降级或插件框架。

LLM 使用 OpenAI 官方 Go SDK 连接百炼兼容接口。百炼没有适用于本项目语音接口的官方 Go SDK，因此 ASR 和 TTS 使用 Go WebSocket 库按官方协议直连。

## 首期不包含

- 设备激活、注册、绑定、每设备凭证和设备管理。
- MySQL 或其他数据库、消息持久化、长期记忆和原始音频存储。
- 管理 API、OpenAPI、管理 UI 和 Prometheus 指标。
- WebSocket 协议 v2/v3、MQTT + UDP、MCP 和固件 OTA。
- 本地 VAD/ONNX、`realtime` 模式、AEC 和全双工说话抢断。
- 多 AI 服务商实现、运行时切换、自动降级和故障转移。
- Docker、多架构镜像、发布流水线和容量 SLA。

## 部署与安全限制

- 首期只要求服务在开发机启动并完成真实设备验收，不交付容器。
- 不规定固定并发数量，但每次部署必须设置有限的最大会话数。
- 所有设备共用一个环境变量注入的 Bearer Token，不提供可信设备身份。
- 百炼 API Key 和设备 Token 不得写入源码、YAML、测试、日志或文档。
- 任何曾暴露在聊天、日志或仓库中的 Key 都必须撤销并重新生成。
- 本阶段只适用于受信任内网，或由外部反向代理保护的私有环境，不可直接作为公网生产服务。

## 完成标准

使用当前未修改固件和真实百炼服务完成以下验收：

1. 设备通过配置发现连接 WebSocket v1，并在 `auto` 模式完成一轮语音问答。
2. 设备连续完成至少一轮依赖前文的对话。
3. 播放中显式中断后不再收到旧回答文本或音频。
4. 断线后设备可以重新连接并继续新对话。
5. 服务端未建立设备档案或消息历史，未保存原始音频、对话正文或完整设备声明。
6. 关键协议、供应商模拟、取消和竞争检测通过自动化测试。

具体消息、状态、配置、资源限制和测试要求以 [Agents 详细基线](../agents/requirements-and-architecture.md) 为准。
