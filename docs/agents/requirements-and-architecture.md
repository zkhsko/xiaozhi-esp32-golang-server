# xiaozhi-esp32-golang-server 架构设计基线

## 1. 文档目的与范围

本文档是 `xiaozhi-esp32-golang-server` 的架构设计基线，用于指导后续实现、重构、审查与验证。

本文只记录系统目标、模块边界、核心流程、关键约束和未决决策，不维护字段级表结构、接口请求响应结构、配置样例、具体参数值或供应商实现细节。

系统提供面向 `xiaozhi-esp32` 固件的服务端能力：

1. **OTA 与设备生命周期**：配置发现、设备激活、用户绑定、出厂凭证管理及设备访问鉴权。
2. **双向语音对话**：通过 WebSocket 承载音频与控制消息，串联 ASR、LLM、TTS 和音频编解码能力。
3. **工具与扩展**：支持设备 MCP 工具、内置 Agent 工具及 LLM 多轮工具编排。
4. **持久化与存储**：通过统一数据库边界管理设备生命周期与 AI 运行时配置，并支持版本化迁移。

## 2. 设计依据与优先级

1. **设备协议兼容性**：服务端设计必须兼容 `xiaozhi-esp32` 固件既有协议和生命周期。
2. **生产代码约束**：架构设计必须具有稳定生产入口，并与现有代码和测试保持一致。
3. **第三方服务约束**：ASR、LLM、TTS 及其他外部服务通过适配器隔离，不向业务层泄露供应商协议。
4. **文档同步关系**：本文档记录详细架构设计；[人类项目概览](../humans/project-overview.md) 仅保留高层摘要。

## 3. 架构与 Package 边界

### 3.1 模块与职责

- `cmd/server`：服务入口，负责配置加载、基础设施初始化、依赖装配和优雅退出。
- `internal/config`：基础设施与会话静态配置的加载、校验及敏感连接信息注入边界。
- `internal/database`：数据库连接、迁移、设备生命周期数据、AI 运行时配置及会话配置快照的数据访问边界。
- `internal/router`：设备生命周期、管理配置和用户操作等 HTTP API 的路由与 Handler 装配。
- `internal/session`：WebSocket 生命周期、鉴权、按设备类型加载 Agent 运行时配置、状态机、语音对话编排、工具调用编排、MCP 协议和并发控制。
- `internal/agentkit`：WebSocket 语音交互链路中供大模型调用的内置 Agent 工具集合，不拥有 WebSocket 连接或会话生命周期。
- `internal/audio`：音频编解码、缓冲和实时下发节奏控制。
- `internal/ai`：ASR、LLM、TTS 的统一抽象、值对象及供应商适配边界。
- `internal/logger`：结构化日志、安全脱敏和诊断限流。
- `internal/server`：HTTP 服务生命周期封装。

### 3.2 依赖拓扑

```text
HTTP / WebSocket 入口 (internal/router)
  ├── OTA / User API  ──>  internal/database (设备生命周期)
  ├── Admin API       ──>  internal/database (设备与 AI 配置)
  └── WebSocket Session (internal/session)
        ├── internal/database (鉴权与 Agent 运行时快照)
        ├── internal/audio
        ├── internal/agentkit
        └── internal/ai
```

上层编排模块只依赖下层抽象。供应商适配器、具体工具和基础设施不得反向依赖 `internal/session`。

### 3.3 AgentKit 结构与职责

`internal/agentkit` 采用单包、按工具分文件的扁平结构：

```text
internal/agentkit/
├── close_session.go
├── current_time.go
└── current_weather.go
```

- 三个文件统一声明 `package agentkit`，通过文件区分工具，不为小型工具机械拆分子包。
- 每个文件负责对应工具的模型描述、参数约束和独立执行逻辑。
- 需要外部服务的工具通过最小依赖接口注入，不直接依赖会话对象。
- `close_session.go` 只表达关闭会话的意图，具体关闭时机和连接清理由 `internal/session` 处理。
- `internal/session` 负责聚合 AgentKit 与设备 MCP 工具、去重、授权、路由和多轮 LLM 编排，不承载具体内置工具实现。

## 4. 数据库与持久化设计

### 4.1 持久化原则

- 业务层通过统一数据访问边界使用关系型数据库，不直接依赖具体数据库驱动。
- 数据库结构变更通过可审计、可排序的版本化迁移管理。
- 激活、绑定、令牌签发及旧数据失效等跨表变更必须具有明确事务边界。
- 数据库凭据与连接信息由外部安全配置注入，不写入代码或公开文档。

### 4.2 数据域与数据表说明

- **`device_hmac_credential`（出厂与激活 HMAC 凭证表）**：保存设备出厂凭证、设备类型及凭证生命周期状态，用于设备身份校验和硬件签名激活。
- **`device_activation`（设备激活关系表）**：记录设备标识之间的激活关系及其生命周期状态。
- **`device_user_ref`（设备与用户绑定关系表）**：记录设备与用户之间的绑定关系，为用户侧设备管理与会话归属提供依据。
- **`device_access_token`（设备鉴权 Access Token 表）**：管理设备访问 WebSocket 服务所需的令牌及其签发、下发、有效和撤销状态。
- **`asr_config`（语音识别配置表）**：保存可复用的 ASR 服务配置，供不同 Agent 组合使用。
- **`llm_config`（大语言模型配置表）**：保存可复用的 LLM 服务配置，定义 Agent 使用的模型能力。
- **`tts_config`（语音合成配置表）**：保存可复用的 TTS 服务与音色能力配置，供 Agent 选择使用。
- **`agent_config`（Agent 配置表）**：将 ASR、LLM、TTS 配置与 Agent 行为配置组合为完整的语音交互运行时方案。
- **`device_type`（设备类型配置表）**：维护设备类型与 Agent 配置的映射，用于 WebSocket 会话建立时选择对应的运行时方案。

#### 配置关系

```text
设备身份与访问凭据
        │
        ▼
   device_type ──> agent_config
                         ├──> asr_config
                         ├──> llm_config
                         └──> tts_config
```

设备接入后按设备类型解析 Agent 配置，再加载其关联的 ASR、LLM 和 TTS 配置，形成当前会话独立的运行时快照。

## 5. 接口设计

接口按业务域组织，本文仅记录职责和边界，不维护具体方法、参数及响应结构。

| 接口域 | 路由边界 | 设计职责 |
| --- | --- | --- |
| OTA 与设备激活 | `/xiaozhi/ota` | 负责配置发现、设备身份验证和激活流程，并向已具备访问资格的设备提供后续连接信息。 |
| 用户设备管理 | `/user-api` | 负责将完成激活校验的设备绑定到当前用户，并建立设备访问凭据。 |
| 设备管理 | `/admin-api` | 负责出厂凭证和设备激活关系的查询与生命周期管理。 |
| AI 配置管理 | `/admin-api` | 负责 ASR、LLM、TTS、Agent 以及设备类型映射的维护，为语音会话提供可动态选择的运行时配置。 |
| 实时语音会话 | `/xiaozhi/v1` | 负责设备鉴权、运行时配置解析、WebSocket 语音交互和 MCP 工具通信。 |

接口层只负责协议适配、输入校验和流程编排；数据一致性、引用约束和生命周期规则由对应业务与数据访问边界负责。敏感配置只允许写入或受控更新，普通查询不得返回凭据原文。

## 6. WebSocket 语音会话设计

### 6.1 连接与准入

- 设备通过受鉴权保护的 WebSocket 入口建立长连接。
- 服务端在连接建立前完成设备身份、协议兼容性和会话容量校验。
- 鉴权失败、协议不兼容或容量不足时，不创建会话资源。

### 6.2 会话初始化

鉴权完成后，服务端根据设备类型加载对应的 Agent 及其 ASR、LLM、TTS 运行时快照，为当前连接创建独立客户端实例。随后客户端与服务端协商会话身份和音频能力；任一必要配置缺失、不可用或初始化超时，都必须在进入正式会话前失败并释放资源。

### 6.3 控制消息

文本消息承载会话初始化、收音控制、中止控制、识别结果、语音合成状态和 MCP 交互。消息解析必须经过类型校验和大小限制。

### 6.4 音频流

二进制消息承载 Opus 音频。上行音频经解码后进入 ASR，下行 TTS 音频经编码和节奏控制后发送给设备；整个链路必须具备有界缓冲和取消能力。

## 7. 工具调用与编排

### 7.1 工具来源与优先级

1. **内置 Agent 工具**：由 `internal/agentkit` 提供，包括当前时间、关闭会话和当前天气等服务端能力。
2. **设备 MCP 工具**：由设备动态声明，并通过 MCP 协议发现和调用。
3. **优先级**：内置工具优先于设备同名工具，避免设备覆盖服务端保留能力。

### 7.2 工具编排规则

- 大模型通过统一工具描述感知可用能力，不感知具体执行位置。
- 工具进入模型上下文前必须完成聚合、去重和会话级授权。
- 内置工具由 AgentKit 执行，设备工具通过 MCP 转发执行。
- 工具结果作为后续模型上下文继续驱动当前轮回复。
- 关闭会话工具只产生关闭意图，会话必须在当前轮最终回复完成后再释放连接。
- 工具调用循环必须具有明确的迭代上限、取消边界和错误收敛策略。

## 8. 状态机与并发资源设计

### 8.1 会话状态机

```text
CONNECTED -> READY -> LISTENING -> PROCESSING -> SPEAKING
                 ^                       |           |
                 +-----------------------+-----------+
```

- 会话状态变更由统一监督流程管理，避免多个异步任务直接竞争状态所有权。
- 中止、错误、超时和连接断开可以从任意状态进入清理流程。
- 每轮交互使用代次隔离，过期异步结果不得影响后续轮次。

### 8.2 资源与并发原则

- 会话数、消息大小、音频缓冲、工具调用次数和历史上下文均必须有界。
- ASR、LLM、TTS、MCP、会话初始化和优雅关闭均必须具备独立超时与取消边界。
- 上下行链路采用背压而不是无界缓存；无法恢复的持续拥塞应主动结束会话。
- 会话资源必须按统一顺序注册和释放，确保并发名额、网络连接和后台任务不会泄漏。
- 服务停止时先停止新会话准入，再在有限宽限期内清理存量会话。

## 9. 配置设计

### 9.1 配置域

- **静态基础设施配置**：服务监听、公开访问地址、HTTP 生命周期、会话资源边界和数据库连接策略。
- **动态 AI 配置**：ASR、LLM、TTS、Agent 组合及设备类型映射由数据库维护，通过管理接口更新，并在会话建立时加载。
- **网络访问配置**：外部 AI 服务的访问地址、代理和调用边界随对应组件配置管理。

静态配置在服务启动阶段完成严格校验；动态配置在保存和会话装配阶段校验，非法或引用不完整的配置不得进入运行时。

### 9.2 敏感配置

数据库连接凭据通过外部安全环境注入。AI 服务凭据随受控组件配置管理，必须作为只写敏感信息处理，不得出现在普通查询结果、日志或公开文档中。

## 10. 安全限制与未决事项

### 10.1 安全设计

- HMAC、访问令牌及其他敏感凭据校验采用抗时序分析的比较方式。
- 日志不得输出访问令牌、HMAC 密钥、系统提示词或原始音频数据。
- 设备标识、异常载荷和高频错误日志必须进行截断、脱敏与限流。
- 设备凭据只在必要流程中暴露，并具有明确的签发、下发、撤销和失效生命周期。
- 公网部署必须由安全传输层保护 WebSocket、HTTP API 和外部服务访问。

### 10.2 未决事项

1. **用户认证与授权体系**：生产级多用户身份认证、会话管理及资源授权模型尚未最终确定。
2. **管理接口鉴权模型**：管理能力需要独立的身份认证和权限边界；接入前只能部署在受信任环境或由外部安全层保护。
3. **生产数据库升级策略**：多实例环境下的迁移协调、兼容窗口和回滚策略尚未最终确定。
4. **激活与绑定事务收敛**：重新激活、旧凭据失效和并发绑定的最终事务边界仍需持续收敛。
